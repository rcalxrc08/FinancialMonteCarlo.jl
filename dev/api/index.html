Metrics

FinancialMonteCarlo.pricer — Function
pricer(mcProcess, rfCurve, mcConfig, payoff)

Monte Carlo estimate of the price of payoff: the mean of the discounted payoff over the simulated paths. The random number generator is reset to the seed of mcConfig first, so the result is reproducible. Returns a vector of prices for a vector of payoffs or a smile; for a smile in CudaMode it is a CuArray, so the computations on the prices can stay on the GPU.

Arguments

  • mcProcess: the model (a single name or multivariate process, or a MarketDataSet).
  • rfCurve: the zero rate curve, e.g. ZeroRate.
  • mcConfig: the MonteCarloConfiguration.
  • payoff: a payoff, a vector of payoffs priced on the same paths, a smile, a FinancialMonteCarlo.Position or, with a MarketDataSet, a FinancialMonteCarlo.Portfolio.

Examples

model = BlackScholesProcess(0.2, Underlying(100.0, 0.01))
mcConfig = MonteCarloConfiguration(10_000, 30)
pricer(model, ZeroRate(0.02), mcConfig, EuropeanOption(1.0, 100.0))
pricer(model, ZeroRate(0.02), mcConfig, [Forward(1.0), AmericanOption(1.0, 100.0, false)])
source
FinancialMonteCarlo.variance — Function
variance(mcProcess, rfCurve, mcConfig, payoff)

Sample variance of the discounted payoff over the simulated paths (a vector for a vector of payoffs or a smile). The variance of the price estimate is this value divided by the number of paths.

Arguments

  • mcProcess: the model.
  • rfCurve: the zero rate curve.
  • mcConfig: the MonteCarloConfiguration.
  • payoff: a payoff, a vector of payoffs or a smile.

Confidence interval at level alpha for the price of payoff, based on the Student t approximation of the Monte Carlo estimator. Returns a tuple (lower, upper), or a vector of them for a vector of payoffs or a smile.

Arguments

  • rfCurve: the zero rate curve.
  • mcConfig: the MonteCarloConfiguration.
  • payoff: a payoff, a vector of payoffs or a smile.

FinancialMonteCarlo.delta — Function
delta(mcProcess, rfCurve, mcConfig, payoff, dS0 = 1e-7)
delta(market, rfCurve, mcConfig, portfolio, underlying_name, dS0 = 1e-7)

Delta of payoff by forward finite difference: the spot of the underlying is bumped by dS0 and the payoff repriced with the same seed. For a MarketDataSet and a FinancialMonteCarlo.Portfolio, only the underlying called underlying_name is bumped (also inside multivariate models); the delta is zero if it is not in the market data set.

Arguments

  • mcProcess: the model (a single name or multivariate process, or a MarketDataSet).
  • rfCurve: the zero rate curve, e.g. ZeroRate.
  • mcConfig: the MonteCarloConfiguration.
  • payoff: a payoff, a vector of payoffs priced on the same paths, a smile, a FinancialMonteCarlo.Position or, with a MarketDataSet, a FinancialMonteCarlo.Portfolio.
  • dS0: spot bump.

For exact pathwise deltas use a dual number as spot, see the Automatic differentiation section of the manual.

source

FinancialMonteCarlo.ZeroRate — Type
ZeroRate(r)
ZeroRate(r::Vector, T)

Zero rate curve used for discounting and for the risk neutral drift. With a number, the rate is constant; with a vector, r holds the instantaneous rates on a uniform grid from 0 to T and a ZeroRateCurve is returned (see FinancialMonteCarlo.Curve). To build the curve from quoted zero rates use FinancialMonteCarlo.ImpliedZeroRate.

Time dependent zero rate curve, holding a curve of instantaneous rates (see FinancialMonteCarlo.Curve). Usually built through ZeroRate or FinancialMonteCarlo.ImpliedZeroRate.

FinancialMonteCarlo.ImpliedZeroRate — Function
ImpliedZeroRate(r::Vector, T::Vector)
ImpliedZeroRate(r::Vector, T)

ZeroRateCurve reproducing the zero rates r quoted at maturities T (or at a uniform grid up to T), i.e. whose instantaneous rate integrates to $r_i T_i$ up to each $T_i$. See FinancialMonteCarlo.ImpliedCurve.

FinancialMonteCarlo.Curve — Function
Curve(r::Vector, T::Vector)
Curve(r::Vector, T)

Curve of instantaneous rates with values r at the sorted times T (or on a uniform grid from 0 to T), linearly interpolated in between. Models only use its integrals over time intervals, both for the drift and for discounting.

source
FinancialMonteCarlo.ImpliedCurve — Function
ImpliedCurve(r::Vector, T::Vector)
ImpliedCurve(r::Vector, T)

Piecewise linear curve of instantaneous rates, starting from zero at time zero, whose integral up to each T[i] equals r[i] * T[i]: use it to turn zero rates (or dividend yields) quoted at maturities T into a FinancialMonteCarlo.Curve. With a scalar T the maturities are T/N, 2T/N, ..., T.

Monte Carlo configuration

FinancialMonteCarlo.MonteCarloConfiguration — Type
MonteCarloConfiguration(Nsim, Nstep, seed::Number)
MonteCarloConfiguration(Nsim, Nstep, method = StandardMC(), seed = 0)
MonteCarloConfiguration(Nsim, Nstep, parallelMode::BaseMode)
MonteCarloConfiguration(Nsim, Nstep, method, parallelMode, init_rng = true)

Settings of a Monte Carlo simulation.

Arguments

  • Nsim: number of simulated paths, must be positive (and even for FinancialMonteCarlo.AntitheticMC).
  • Nstep: number of time steps of each path, must be positive.
  • method: an AbstractMonteCarloMethod: FinancialMonteCarlo.StandardMC, FinancialMonteCarlo.AntitheticMC, FinancialMonteCarlo.SobolMode or FinancialMonteCarlo.ControlVariates.
  • parallelMode: a BaseMode owning the random number generator: FinancialMonteCarlo.SerialMode (default, with the given seed), FinancialMonteCarlo.MultiThreading, MultiProcess (with Distributed) or CudaMode (with CUDA).
  • init_rng: when true, every metric resets the generator to its seed before simulating.

Examples

MonteCarloConfiguration(10_000, 30)
MonteCarloConfiguration(10_000, 30, FinancialMonteCarlo.AntitheticMC())
MonteCarloConfiguration(10_000, 30, FinancialMonteCarlo.MultiThreading())
source

FinancialMonteCarlo.ControlVariates — Type
ControlVariates(variate, conf_variate, method = StandardMC())

Control variates method for MonteCarloConfiguration. A pilot simulation with configuration conf_variate estimates the optimal coefficient and the price of the control variate (exact when variate is a Forward); the main simulation then uses method. The control must have the same maturity as the priced payoff.

FinancialMonteCarlo.SerialMode — Type
SerialMode(seed = 0, rng = MersenneTwister())

Single threaded simulation drawing from rng, which is reset to seed by every metric. Any Random.AbstractRNG can be used.

source
FinancialMonteCarlo.MultiThreading — Type
MultiThreading(sub_mod = SerialMode(), numberOfBatch = Threads.nthreads(), seeds = sub_mod.seed .+ (1:numberOfBatch))

Parallel mode splitting the paths into numberOfBatch batches priced on different threads, each with its own seed from seeds and its own copy of the generator of sub_mod, a FinancialMonteCarlo.SerialMode. The result does not depend on the number of threads. Prices are the averages of the batch prices, weighted by their number of paths.

Generators that cannot be copied (VectorizedRNG) and FinancialMonteCarlo.SobolMode are not supported. Of the automatic differentiation backends, only the forward ones are supported: the batches would write to the same tape of ReverseDiff, and Mooncake cannot differentiate through tasks.

source
FinancialMonteCarlo.MultiProcess — Type
MultiProcess(sub_mod = SerialMode(), nbatches = nworkers(), seeds = sub_mod.seed .+ (1:nbatches))

Parallel mode splitting the paths into nbatches batches priced on the workers of Distributed, which needs using Distributed, each with its own seed from seeds and its own copy of the generator of sub_mod, a FinancialMonteCarlo.SerialMode. The result does not depend on the number of workers, which take the next batch when they finish one. Prices are the averages of the batch prices, weighted by their number of paths.

The workers must load the package and everything the priced objects use (@everywhere using FinancialMonteCarlo). To differentiate through a pricer, the function must exist on the workers too (@everywhere f(x) = ...): an anonymous function defined only on the main process raises an error. simulate and distribution send all the paths back to the main process, which can take longer than simulating them; the other metrics send back only their results.

init_rng = false, generators that cannot be copied (VectorizedRNG) and FinancialMonteCarlo.SobolMode are not supported. Of the automatic differentiation backends, only the forward ones are supported.

source
FinancialMonteCarlo.CudaMode — Type
CudaMode(seed_cpu = 0, seed_gpu = 0, rng = MersenneTwister())

Simulation on the GPU, which needs using CUDA. Every metric resets rng to seed_cpu and the CURAND generator to seed_gpu.

Models

FinancialMonteCarlo.simulate — Function
simulate(mcProcess, zeroCurve, mcConfig, T)

Simulate the paths of the underlying of mcProcess from time 0 to T, under the risk neutral measure given by zeroCurve.

Returns an Nsim × (Nstep + 1) matrix whose i-th row is the i-th path on the uniform time grid 0:T/Nstep:T (the first column is the spot). For multivariate processes, a vector with one such matrix per component. The element type is inferred from the inputs, so it can be a dual number.

New models implement the in-place simulate!(S, mcProcess, zeroCurve, mcConfig, T).

source
simulate(engine, mcConfig, T)

Simulate the paths of an engine (e.g. BrownianMotion), which needs no zero rate curve, from time 0 to T. Returns an Nsim × (Nstep + 1) matrix, one path per row.

source
FinancialMonteCarlo.BlackScholesProcess — Type
BlackScholesProcess(σ, underlying)

Black-Scholes model: under the risk neutral measure the underlying follows a geometric Brownian motion $dS_t = (r_t - d_t) S_t\,dt + σ S_t\,dW_t$.

Arguments

  • σ: volatility, must be positive.
  • underlying: an Underlying with spot price and dividends.

Examples

model = BlackScholesProcess(0.2, Underlying(100.0, 0.01))
pricer(model, ZeroRate(0.02), MonteCarloConfiguration(10_000, 30), EuropeanOption(1.0, 100.0))
source
FinancialMonteCarlo.HestonProcess — Type
HestonProcess(σ, σ₀, λ, κ, ρ, θ, underlying)

Heston stochastic volatility model:

\[dS_t = (r_t - d_t) S_t\,dt + \sqrt{v_t} S_t\,dW_t, \qquad dv_t = κ^*(θ^* - v_t)\,dt + σ \sqrt{v_t}\,dZ_t, \qquad d\langle W, Z\rangle_t = ρ\,dt,\]

with risk neutral parameters $κ^* = κ + λ$ and $θ^* = κθ / (κ + λ)$. Both are simulated with an Euler scheme on the log price, flooring the variance at a tiny positive value.

Arguments

  • σ: volatility of the variance, must be positive.
  • σ₀: initial volatility, must be positive.
  • λ: market price of volatility risk.
  • κ: speed of mean reversion ($κ + λ$ must not be zero).
  • ρ: correlation between the Brownian motions, in $[-1, 1]$.
  • θ: long term variance.
  • underlying: an Underlying with spot price and dividends.
source
FinancialMonteCarlo.KouProcess — Type
KouProcess(σ, λ, p, λ₊, λ₋, underlying)

Kou jump diffusion: the log price is a Brownian motion with volatility σ plus a compound Poisson process with intensity λ and double exponential jumps (up with probability p, with exponential sizes of rate λ₊ up and λ₋ down). The drift is chosen to make the discounted price a martingale.

Arguments

  • σ: volatility, must be positive.
  • λ: jump intensity, must be positive.
  • p: probability of an up jump, in $[0, 1]$.
  • λ₊: rate of the exponential up jumps, must be greater than 1 (for a finite forward).
  • λ₋: rate of the exponential down jumps, must be positive.
  • underlying: an Underlying with spot price and dividends.
source
FinancialMonteCarlo.MertonProcess — Type
MertonProcess(σ, λ, μ_jump, σ_jump, underlying)

Merton jump diffusion: the log price is a Brownian motion with volatility σ plus a compound Poisson process with intensity λ and normally distributed jumps. The drift is chosen to make the discounted price a martingale.

Arguments

  • σ: volatility, must be positive.
  • λ: jump intensity, must be positive.
  • μ_jump: mean of the jumps of the log price.
  • σ_jump: standard deviation of the jumps of the log price, must be positive.
  • underlying: an Underlying with spot price and dividends.
source
FinancialMonteCarlo.VarianceGammaProcess — Type
VarianceGammaProcess(σ, θ, κ, underlying)

Variance Gamma model: the log price is a Brownian motion with drift θ and volatility σ, evaluated at a gamma subordinator with unit mean rate and variance rate κ. The drift is chosen to make the discounted price a martingale.

Arguments

  • σ: volatility of the subordinated Brownian motion, must be positive.
  • θ: drift of the subordinated Brownian motion.
  • κ: variance rate of the subordinator, must be positive.
  • underlying: an Underlying with spot price and dividends.

The parameters must satisfy $1 - σ^2 κ / 2 - θ κ > 0$ for the forward to be finite.

source
FinancialMonteCarlo.NormalInverseGaussianProcess — Type
NormalInverseGaussianProcess(σ, θ, κ, underlying)

Normal Inverse Gaussian model: the log price is a Brownian motion with drift θ and volatility σ, evaluated at an inverse gaussian subordinator with unit mean rate and variance rate κ. The drift is chosen to make the discounted price a martingale.

Arguments

  • σ: volatility of the subordinated Brownian motion, must be positive.
  • θ: drift of the subordinated Brownian motion.
  • κ: variance rate of the subordinator, must be positive.
  • underlying: an Underlying with spot price and dividends.

The parameters must satisfy $1 - σ^2 κ - 2 θ κ > 0$ for the forward to be finite.

source
FinancialMonteCarlo.LogNormalMixture — Type
LogNormalMixture(η, λ, underlying)

LogNormal mixture model: the underlying is the weighted sum $S_t = \sum_i λ_i S^i_t$ of geometric Brownian motions with the risk neutral drift and volatilities η, all starting from the spot.

Arguments

  • η: vector of volatilities, all positive.
  • λ: vector of the first length(η) - 1 weights, positive and summing to at most 1 (the last weight is 1 - sum(λ)).
  • underlying: an Underlying with spot price and dividends.
source
FinancialMonteCarlo.ShiftedLogNormalMixture — Type
ShiftedLogNormalMixture(η, λ, α, underlying)

Shifted LogNormal mixture model: a LogNormalMixture on $(1 - α) S_0$ plus a deterministic shift $α S_0$ growing at the risk neutral rate.

Arguments

  • η: vector of volatilities, all positive.
  • λ: vector of the first length(η) - 1 weights, positive and summing to at most 1.
  • α: shift, as a fraction of the spot price.
  • underlying: an Underlying with spot price and dividends.

FinancialMonteCarlo.payoff — Function
payoff(S, payoff, rfCurve, mcConfig, T1 = maturity(payoff))

Discounted payout of payoff along each simulated path in S, i.e. the vector whose mean is the price. S is the output of simulate up to time T1, which can be later than the maturity of the payoff (as happens when several payoffs are priced on the same paths).

This is the generic interface: each payoff family has an engine implementing it on top of the payoff specific payout, see the Extending section of the manual.

FinancialMonteCarlo.BermudanOption — Type
BermudanOption(T, K, isCall = true)

Bermudan vanilla option, exercisable at the dates in T (the last one being the maturity), with exercise value $\max(S_t - K, 0)$ (call) or $\max(K - S_t, 0)$ (put). Priced with the Longstaff-Schwartz regression. Exercise dates should lie on the simulation time grid.

Arguments

  • T: sorted vector of positive exercise dates.
  • K: strike, must be positive.
  • isCall: true (default) for a call, false for a put.

FinancialMonteCarlo.EuropeanOptionND — Type
EuropeanOptionND(T, K, isCall = true)

European option on the sum of the underlyings of a multivariate model, paying $\max(\sum_i S^i_T - K, 0)$ (call) or $\max(K - \sum_i S^i_T, 0)$ (put) at maturity T.

Arguments

  • T: time to maturity, must be positive.
  • K: strike, must be positive.
  • isCall: true (default) for a call, false for a put.

FinancialMonteCarlo.EuropeanOptionSmile — Type
EuropeanOptionSmile(T, K::Vector, isCall::Vector{Bool})

Set of EuropeanOptions with the same maturity T and strikes K, each a call or a put according to isCall. They are priced together on the same paths: pricer, variance, confinter, delta and rho return one value per strike. In CudaMode the strikes are computed in one kernel and the results are a CuArray, except for the tuples of confinter.

FinancialMonteCarlo.MarketDataSet — Type
MarketDataSet

Dictionary from underlying names to models, built with name → model and joined with +. The name of a multivariate model joins the names of its components with _, e.g. "ENI_AAPL".

source
FinancialMonteCarlo.Position — Type
Position

Linear combination of payoffs on the same underlying, stored as a dictionary from payoff to weight. Positions are built with +, -, * and / on payoffs and numbers, e.g. 2.0 * EuropeanOption(T, K) - Forward(T), and are priced on a single simulation.

source
FinancialMonteCarlo.Portfolio — Type
Portfolio

Dictionary from underlying names to FinancialMonteCarlo.Positions, built with name → payoff (see →) and joined with +. Priced against a MarketDataSet.

source
